Rocketry @ VT | 2.4GHz and 915MHz Transciever
This board is me applying my knowledge from my keyboard projects into something that is helpful for the team. The intent of this board is to facilitate all RF telemetry signals through one board. The bands for this board are 2.4GHz Bluetooth and 915MHz LoRa Radio. Past rockets have had 915MHz and a redundant 2.4GHz system that wasn't used much. This board is equipped with a range extender which boosts the signal by 18dB, providing a 6x to 10x increase in range. The board takes in the raw 2S battery power, stepping down from about 8.4V to 5V with a switching buck converter, and down again from 5V to 3.3V with an LDO. While the switching regulator can introduce noise which isn't optimal for an RF board, the LDO would have to dissipate about 2W of heat, which is too much for one component to reliably handle. The board breaks out into 2 SMAs, 2 i2cs buses for sensors, USB, UART for a master controller, and an SWD and both SPIs broken out for debugging.

fmov
What started as a project to create chess videos programmatically turned into the most efficient python library for generating videos, currently at 10k+ downloads on PyPi. I simply wanted something that would handle the interactions between FFmpeg and python, without having to hard-code shell commands. The library is simple, taking in image objects from PIL, piping them into FFmpeg, handling all of the flags for rendering, and finally assembling the video with any sound effects. Got to learn a lot about the process of creating effective projects for real users and writing documentation. 'pip install fmov'

K42
A custom wireless split ergonomic mechanical keyboard with a 42 key layout (21 per half). Built around a bare-die nRF52840 MCU, with haptic feedback via a DRV2605L driver and LRA actuator, per-half OLED displays, and Kailh Choc V1 hotswap sockets. Designed in KiCad, from schematic capture through JLCPCB PCBA. Worked with impedance matching networks using a pi filter as well as trace antenna for 2.4GHz BLE connectivity. Also evaluated the margins on selling the completed keyboard pre-assembled, and found the difficulty between trying to stay competitive in the market and provide a scalable completed product.

DOOM in a Calculator
What started as a test for 3D using an experimental new feature in the Desmos calculator turned into a project that I worked on in my free time to get DOOM up in a graphing calculator. The underlying mechanic that makes this version so much more performant is the fact that the rendering is handled by the 3D version of Desmos, since they added a feature that allowed triangles outside of the bounding box. Since that handled all the raytracing, all I had to do was implement the math behind movement, triangle placement, getting images to be rendered through compiling images into triangle code for the graph, and most difficult of all: textures. There is a way to run shaders on surfaces in the calculator, but they take in an (x, y, z) value, and theres no way for it to store images, since multidimensional lists are unallowed. The way around this was I ran each RGB channel of each image texture through a fourier transform to 'vectorize' an image by mapping (u,v) coordinates with math functions. The coefficients generated could be imported into Desmos, and all that had to be done was mapping and tiling based on the orientation of the map. The final version ran at around 10fps which is much better than any other attempt. I found this project fulfilling because I couldn't just use AI or look up solutions, but rather I had to invent new solutions on my own.
